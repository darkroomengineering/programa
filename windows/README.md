# Programa for Windows

Programa's Windows frontend uses C# on .NET 10 and native WinUI 3 controls. The portable Rust core owns workspace, pane, surface, selection, split, and tab-order behavior. `programa_terminal.dll` owns each ConPTY session and terminal model; the WinUI shell keeps one `TerminalView` alive per core surface ID so selecting, splitting, and reordering controls never restarts a shell.

## Build on Windows

Install the .NET 10 SDK, stable Rust MSVC toolchain, Visual Studio Build Tools with the Desktop development with C++ workload, and a current Windows SDK. Then run from PowerShell at the repository root:

```powershell
rustup default stable-msvc
rustup target add x86_64-pc-windows-msvc
./scripts/build-windows.ps1 -Version 0.4.123 -Build 123 -Commit 0123456789abcdef0123456789abcdef01234567 -OutputDirectory ./artifacts/windows
```

The output directory must be new or empty. The script formats and tests both Rust libraries, runs the managed projection tests, publishes the unpackaged self-contained WinUI application, validates its x64 PE header and exact `--version` output, and emits only these byte-identical files:

- `programa-windows.exe`
- `programa-windows-<build>.exe`

Windows App SDK single-file publishing extracts its bundled managed, WinUI, `programa_core.dll`, `programa_terminal.dll`, `conpty.dll` and `OpenConsole.exe` dependencies into the .NET single-file extraction area on first launch. The last two come from Microsoft's `Microsoft.Windows.Console.ConPTY` NuGet package (the ConPTY Windows Terminal ships): terminal sessions run on that `OpenConsole.exe` rather than the inbox conhost, which mangles OSC color queries and repaints the screen. `--verify-native-libraries` fails when either file is missing, and `launch.log` records `conpty=bundled` or `conpty=inbox` on every start. It does not download code or require a separately installed Windows App SDK runtime.

Release builds are signed via Azure Trusted Signing once the account is configured (see `docs/windows-signing.md`). Until then, `programa-windows.exe` ships unsigned and SmartScreen shows "Run anyway" the first time someone launches it.

For an ordinary development build after the native DLLs exist:

```powershell
dotnet build windows/Programa/Programa.csproj -p:ProgramaNativeDirectory=C:\path\to\native-dlls
```

## Windows behavior

The app uses WinUI `TabView` document tabs: drag a tab to reorder it, onto another pane's tab strip to move it there (in this window or another Programa window), or out past the edge of every Programa window to open it in a new window under the release point, as on macOS. Its terminal moves with it, still running with its scrollback. Released over a window but off a tab strip, a tab stays where it was; Escape cancels the drag; the app's only tab stays put. Each pane has its own tab strip, and recursive WinUI `Grid` layouts provide draggable native split dividers. Closing a pane's final tab collapses that pane; closing a workspace's final tab closes the workspace, and closing the last workspace closes the window. A resizable sidebar on the left lists the workspaces, as on macOS: each row shows the name you gave it (or the focused terminal's title) and the most urgent program status of its terminals; right-click a row for the workspace menu (pin, color, description, move, rename, close). Switching workspaces keeps every terminal running.

Agent status follows the macOS sidebar indicator: each row shows the worst state among its terminals as a pill (Needs input, Working, Done, Error or Idle), the time since the last report, and the agent's logo, which also replaces the tab icon. A working or needs-input agent with no report for 10 minutes reads "(stale)". The state comes from OSC 7501 program status, which Claude Code 2.1.295 and later sends on its own once the terminal answers its probe; nothing needs installing. Claude Code skips the probe when `CLAUDE_CODE_DISABLE_TERMINAL_TITLE` is set, which happens when Programa itself is started from inside a Claude Code session, so start it from the Start menu. Agents that report nothing themselves (Codex, OpenCode, Gemini CLI, Copilot CLI, Cursor Agent, Aider) get their status from the screen every 2 seconds, matched against the same manifests as macOS ([agent detection manifests](../docs/agent-detection-manifests.md)), with your overrides in `%USERPROFILE%\.config\programa\agent-detection`; a shell with nothing running under it ends the detection, and any OSC 7501 or `programa set-agent-state` report wins. Of the agent hooks, Windows runs Claude Code's (below); the badge still follows Claude's own status, and the hooks feed resume and event routes. The window uses the Mica backdrop, and its toolbar shares the title bar row as on macOS: Notifications, New Workspace and Toggle Sidebar sit at the sidebar's trailing edge, the Windows caption buttons at the right, and the rest of the row (including the sidebar's top) drags the window. The end of each pane's tab strip holds Split Right, Split Down, Zoom Pane (dimmed with one pane) and Close Tab, acting on that pane (the macOS 26 pane header). Settings is at the foot of the sidebar. WinUI supplies keyboard focus, system theme and high-contrast behavior, accessibility peers, DPI scaling, and native dialogs.

Notifications follow macOS too. A program can ask for one with `OSC 777;notify;title;body` (Claude Code does, for permission prompts and when it waits for input) or `OSC 9;body`, and a terminal whose agent status enters Needs input, Done or Error posts one, at most once per 10 seconds per terminal. A terminal you are looking at never notifies. Otherwise a Windows notification appears, the tab gets a dot, its pane a ring while that tab is shown, the sidebar row an unread count, and the bell in the toolbar turns the accent color. The bell opens the notifications panel; clicking an entry or a Windows notification goes to its terminal, and looking at a terminal marks its notifications read. `Ctrl+Shift+U` jumps to the latest unread.

New terminals run PowerShell with Programa's shell integration, started after your profile with `-NoExit -EncodedCommand` so the script execution policy does not block it. At each prompt it reports the working directory (OSC 7), the prompt marks (OSC 133) and a title naming the directory, keeping whatever prompt your profile set. New tabs and splits start in the focused terminal's directory, and each sidebar row shows the focused terminal's git branch (read from the repository files) and its directory, left out when it is `~` or repeats the title. Under them, a link names the branch's pull request and its state ("PR #12 open"), looked up with the GitHub CLI (`gh pr list --head`) every 30 seconds as on macOS; without `gh` signed in, the line stays hidden. Every terminal gets `PROGRAMA_SURFACE_ID`, `PROGRAMA_WORKSPACE_ID` and their older aliases, as on macOS.

Every terminal has the `programa` CLI on `PATH` (it ships as `bin\programa.exe` next to the app) and `PROGRAMA_SOCKET_PATH` naming the control pipe, `\\.\pipe\programa-%USERNAME%` (development builds use `programa-dev-%USERNAME%`). The CLI speaks the same v2 JSON lines as the macOS socket and covers `ping`, `identify`, `tree`, workspaces (`new-workspace`, `select-workspace`, `rename-workspace`, `close-workspace`), terminals (`new-surface`, `new-split`, `focus-surface`, `close-surface`, `send`, `read-screen`), notifications (`notify`, `list-notifications`, `clear-notifications`), ports (`list-ports`, `stop-port`), worktrees (`worktree create`, `open`, `remove`, `list`, and `race`), layouts (`layout save`, `apply`, `list`), windows (`list-windows`, `new-window`, `move-workspace-to-window` and more), `markdown open`, `review`, `resume`, `usage` and `set-agent-state`; `programa help` lists the flags. Commands default to the terminal they run in and never take focus, except `select-workspace` and `focus-surface`. The pipe accepts only the current user.

`programa-mcp`, the MCP server agents use to drive Programa ([MCP server](../docs/mcp-server.md)), ships as `bin\programa-mcp.exe`, copied at launch with the `programa` CLI to `%LOCALAPPDATA%\Programa\bin` (the app itself unpacks to `%TEMP%`, which temp cleanup can empty). Claude Code started in a Programa terminal gets it automatically as a server named `programa`: the PowerShell integration wraps `claude` to pass `--mcp-config=` a config the app writes to `%LOCALAPPDATA%\Programa\mcp.json`, nothing is written to your Claude config, and your own `--mcp-config` or `--strict-mcp-config` and the `mcp` and `config` subcommands pass through untouched. Its tools are the running app's control methods (`surface_read_text`, `worktree_create`, `review_open` and so on, with the focus-moving ones named `focus_…`), with input schemas from the macOS contract, and its resources are `programa://tree` (every window) and `programa://surface/<id>/text?lines=n`. For another MCP client, point it at that executable; it finds the app through `PROGRAMA_SOCKET_PATH` or the default pipe.

The Ports button beside Settings counts the TCP ports that programs started from Programa terminals listen on, and appears only while one does. It opens Listening Ports, grouped by workspace, with Open in browser, Copy URL, Reveal in workspace and Stop for each, plus a Left running section for listeners whose terminal closed. Windows has no SIGTERM, so Stop asks first and then sends Ctrl+C through the program's terminal, force-stopping it if it still runs 3 seconds later; a process left running is force-stopped at once. `programa list-ports` and `programa stop-port <port>` (or `--pid`) do the same from a terminal, over `ports.list` and `ports.stop`. The list is rescanned every 3 seconds.

The drive button beside Settings opens Storage, as on macOS: free and total space on the home folder's drive; Live sessions, the disk use of each workspace directory (the home folder and drive roots left out) with its `node_modules`, `build`, `dist`, `.next`, `target` and similar folders of 50 MB or more; the removable linked worktrees of the repositories open in workspaces and under the worktrees folder, with why each other one is kept; and package manager caches (npm, pnpm, Yarn, Bun; Xcode and Android caches are macOS-only), with blocked ones and why. Worktree and cache results are kept five minutes, session sizes two. Each Clean lists what it would remove with sizes and paths and asks first; the worktree Clean skips the idle wait but keeps dirty, unmerged, open or env-file-holding worktrees, and removes with `git worktree remove` without `--force`, never deleting branches. A cache Clean runs the manager's own command (`npm cache clean --force`, `pnpm store prune`, `yarn cache clean`, `bun pm cache rm`), or empties the folder when the manager is not installed, and nothing is cleaned while that manager is installing. Cache paths must be named like a cache or store, outside any repository, reached without junctions. `programa storage scan` and `programa storage clean [--dry-run] [--include-external] [--now] [--path DIR]... [--packages | --caches] [--item ID]...` do the same from a terminal, over `storage.scan` and `storage.clean`. Windows cannot read another process's working directory, so a worktree a process works in is not reported as `process_running`; Windows refuses to delete it and the worktree is kept as `git_refused`. The six-hourly pass that removes merged worktrees also cleans idle package caches with `storage.autoCleanCaches` (default on): `pnpm store prune` every time, the other caches after 14 days unused. Free space is checked 60 seconds after launch and every 15 minutes; below `storage.lowDiskWarningGB` (default 20, `0` turns it off) a toast says so, once until space rises 5 GB above the threshold, and clicking it opens Storage. Both settings are in Settings > Storage.

The gauge button after Ports, Provider Usage, opens how much of your Claude and OpenAI rate limits is left, as on macOS, read each time it opens ("Loading usage…" until the first answer). Claude appears when the `claude` command is found (on `PATH`, `%USERPROFILE%\.local\bin` or `%APPDATA%\npm`), `claude auth status` says you are signed in, and Claude Code's statusline wrote `%USERPROFILE%\.claude\tmp\rate-limits.json` within the last hour (some setups never write it; Claude is then left out), with its Current session and Weekly rows. OpenAI appears when `codex` is found and signed in: `codex app-server` is asked for the account and the unified rate limits, with the plan, credits and reset credits in its header and its windows as Current window and Weekly. Each read has 5 seconds. Each row shows what is left, a bar that turns orange from 60% used and red from 85%, and when it resets; a provider that could not be read shows an error line, and with neither the panel says "No usage available". Settings > Sidebar > Show Provider Usage, or `sidebarAppearance.showClaudeQuota` in settings.json, hides the button.

`programa worktree create <branch>` checks out a git worktree and opens it as its own workspace named after the branch, as on macOS: an existing local branch is checked out, otherwise it is created from `--base` (default `HEAD`), at `--path` or `%USERPROFILE%\.programa\worktrees\<repo>\<branch-slug>`. `worktree open <path-or-branch>` opens an existing worktree (or returns the workspace already on it), `worktree list` marks the open ones, and `worktree remove` closes its workspace and removes the worktree, never the branch, refusing one with uncommitted changes unless `--force`. `--repo` defaults to the current directory, and nothing takes focus unless `--focus`. `--layout <name>` applies a saved layout rooted at the worktree. `programa race "<prompt>"` fans one prompt across `--n` agents (default 3, up to 8; `--agent claude|opencode|codex`), each on its own `<prefix>/<n>` worktree and workspace numbered after the existing ones, without taking focus. `worktree create --from-issue <n>` reads the GitHub issue with `gh issue view` and names the branch `issue-<n>-<title-slug>` (a branch you give wins); `--agent claude|opencode|codex` then starts that agent on the issue, pointed at a prompt file in `%TEMP%\programa-issue-prompts` (kept 7 days) so the issue text is never typed into the shell. `worktree open --all` opens every worktree of the repo not open yet. A worktree's workspace nests in the sidebar under the workspace open on the repository's main checkout, whose row becomes a folder with an arrow that collapses its worktrees; selecting a hidden one opens the folder. Every 6 hours (first two minutes after launch), a worktree under the worktrees folder is removed with `git worktree remove`, its branch kept, when its branch is merged into the remote default branch (or its upstream was deleted), it has no changes, holds no ignored `.env*` file outside `node_modules` and no other ignored file outside build and dependency folders, no workspace is open on it, and it was not used for a day, as on macOS; `worktrees.directory`, `worktrees.autoRemoveMerged` and `worktrees.autoRemoveAfterHours` in settings.json apply, and each removal is written to `launch.log`.

Named layouts use the macOS files and format ([Saved layouts](../docs/programa-json.md#saved-layouts)), in `%USERPROFILE%\.config\programa\layouts`. `programa layout save <name>` records the selected workspace's splits, tab names and directories (relative to the focused terminal's directory); `layout apply <name>` opens it in a new workspace without taking focus, or fills a single-tab workspace given with `--workspace`; `layout list` lists them. A file can add `command`, `env` and `focus` per terminal by hand. The command palette has Save current layout…, Apply, Rename and Delete layout: <name>, and the built-in Agent and Shell and Three Agents presets, which run `claude`. A broken file shows its reason in the palette. The palette also lists the `commands` and `recipes` of `programa.json` ([programa.json](../docs/programa-json.md)) as Custom: and Recipe: <name>, searchable by their `keywords`: from the nearest `programa.json` at or above the focused terminal's directory, then `%USERPROFILE%\.config\programa\programa.json`, the nearer file winning a name both use (a file that does not load lists nothing and is noted in `launch.log`). A command types its text and Return into the focused terminal, or opens its `workspace` (directory, color, layout; `restart` `ignore`, `recreate` or `confirm` for one of that name); a recipe types its prompt without Return. Each `parameter` is asked for first and fills its `{{name}}`. Trust works as on macOS: anything from a project file asks first, showing exactly what will run (every surface's command, directory and variables for a workspace), until you tick Always trust commands from this folder, which trusts the git root (or the file's folder) for that file's current content; a later change to a command asks again. The global file is always trusted, and `confirm: true` always asks. Command text with control characters, and recipe text with line breaks, is refused. Trusted roots are kept in `%LOCALAPPDATA%\Programa\trusted-directories.json` and listed under Settings > Custom Commands, or set by `customCommands.trustedDirectories` in settings.json. Ctrl+Alt+Shift+C opens a new workspace running Claude Code in the focused terminal's directory (⌘⇧C on macOS, which is copy on Windows).

`programa markdown <file>` (or `markdown open <file>`) opens a markdown file in a new pane beside the terminal, as on macOS, without taking focus unless `--focus`; `--direction down` stacks it instead. It renders GitHub-flavored markdown (tables, task lists, code), reloads when the file changes on disk, opens web links in your browser, and comes back with the session. Windows splits only right or down, so `left` and `up` open right and down.

The diff review panel works as on macOS: **Review changes** in the command palette, or `programa review open`, splits a panel beside a terminal showing its uncommitted changes (`git diff HEAD` plus untracked files; `--mode branch --base-branch <ref>` diffs the branch since its merge base instead). Click a line number to comment, Shift+click to extend the range, Ctrl+Enter to add; **Send to agent** pastes every comment into that terminal as `path:start-end — text` lines under "Code review comments (N):" and submits them, refusing while its agent waits on an approval prompt. The panel refreshes itself when the agent finishes a turn, keeps comments whose lines moved (flagged), and comes back with the session (comments do not). `programa review refresh`, `review comment add|remove|list` and `review send` work on the panel from the CLI. Each time an agent starts a turn (its status goes to Working from idle or done; a prompt answered mid-turn is the same turn), its repository's files, tracked and untracked, are saved as a checkpoint under `refs/programa/checkpoints/`, never touching the index, `HEAD` or branches; the newest 20 per tab are kept, and a turn with over 500 changed paths or an untracked file over 10 MB is skipped. The review panel's **Revert Files to Before Last Turn** puts the files back as they were (the conversation is not rewound), saving the current files first so the same button then reads **Undo File Revert**. Closing a workspace deletes its checkpoints.

Each terminal also remembers the last Claude Code session it ran and saves it with the session, for when its shell did not survive (a reboot, or no terminal host). After a relaunch, **Resume Agent Session** in the command palette (shown when the focused terminal has one and nothing runs in it) or `programa resume` types `claude --resume <id>` at its prompt, entering the session's directory first when the terminal is elsewhere; `--print` prints the command instead, and `--session <id> --provider claude|codex|opencode` resumes a given id. The session is the one Claude Code reports through its SessionStart hook: the PowerShell `claude` function also passes `--settings=` a file the app writes to `%LOCALAPPDATA%\Programa\claude-hooks.json`, whose hooks run `programa claude-hook`, as the macOS wrapper's do, each report carrying Claude's session id: SessionStart sends `agent.event` `session.started` and `idle`, UserPromptSubmit `working`, Stop `idle`, Notification `agent.needs_input` (a permission request, or a wait for you as a question; anything else is a notification and `idle`), PostToolUse (and PostToolUseFailure) resumes `working` and clears the workspace's notifications, and SessionEnd sends `session.exited`, clears the state and stops the session's running helpers. As on macOS, PermissionRequest records which agent of the pane has a prompt open (`%TEMP%\programa-claude-permission-*`), so a subagent's finished tool never ends the main agent's stop for input, and PreToolUse (async) keeps an open AskUserQuestion, whose notification then reads as that question instead of a permission request. Your own `--settings` passes through, and your own hooks still run. Claude started without the function (its full path, another shell) falls back to the newest session Claude Code wrote in the terminal's directory (`%USERPROFILE%\.claude\projects`) when a turn ended. The hooks also keep each live session's workspace, pane, directory and transcript in `%USERPROFILE%\.programa\claude-hook-sessions.json` (7 days), and SessionEnd moves it to `agent-last-sessions.json` (one per pane, 50, 7 days), as on macOS. `programa usage [--workspace ID] [--json]` lists those sessions by workspace with the tokens each transcript records ([agent-usage.md](../docs/agent-usage.md)): input, output, cache read and cache write, every message counted once, subagent transcripts included, no cost. A session without a transcript path is found by id under `%CLAUDE_CONFIG_DIR%` (default `%USERPROFILE%\.claude`) or `%CODEX_HOME%` (default `%USERPROFILE%\.codex`), one whose transcript is gone is skipped and counted, and a closed workspace shows by its id.

Codex reports to Programa once you run `programa codex install-integration` (as on macOS; it shows the changes and asks first, `--yes` skips the question): it adds Programa's SessionStart, UserPromptSubmit, Stop, PermissionRequest and SessionEnd hooks to `%CODEX_HOME%\hooks.json` (default `%USERPROFILE%\.codex`), leaving your other hooks where they are, and trusts them in `config.toml` between `# BEGIN programa` and `# END programa`, since Codex skips hooks nobody trusted; a trust entry you wrote yourself is left alone with a warning. If Codex still lists them as new under `/hooks`, trust them there. Codex runs hooks through `cmd.exe` on Windows, so each is `if exist "<programa.exe>" "<programa.exe>" codex-hook <event>` and does nothing once Programa is gone or outside a Programa terminal. The hooks report Codex's session (so **Resume Agent Session** and `programa resume` type `codex resume <id>`), Working on a prompt, Needs input on a permission request (with the command it wants to run), Idle when it stops, and the end of the session, which `programa usage` then counts from Codex's rollout transcript. `programa codex uninstall-integration` removes exactly what it added.

Spawning helpers and authoring detection manifests work as on macOS. `agent.spawn` starts a helper in a workspace of its own, nested under its parent's, in the parent's directory, with `initial_command` and `initial_env`, named after its task's first line, else its role, else "Helper N"; with `needs_isolation`, `repository_path` and `branch`, in a new git worktree of the parent's repository instead (`repository_mismatch` for another repository). Neither takes focus, and the helper is in `agent.task.list` from the start. `agent.detection.list` shows the loaded manifests (bundled or your override, the process names, whether an override shadows a bundled one, and every state's patterns), and the files rejected for patterns that do not compile; `agent.detection.classify` reports which manifest and state a surface's screen reads as, and the pattern that matched. The CLI has `agent-detection list`, `agent-detection test [AGENT]` and `agent-detection scaffold <AGENT> [--force]`, which writes a starter manifest from the surface's screen to `%USERPROFILE%.configprogramaagent-detection` (a bundled agent needs `--force`, and then starts from its bundled patterns).

Helpers work as on macOS ([Helpers popover](../docs/workspace-interface.md#helpers-popover)): Claude Code subagents, through the SubagentStart and SubagentStop hooks, and anything reported with `agent.task.start`, `update`, `finish`, `finish_session` and `list` ([socket API](../docs/socket-api.md#agenttask)). A workspace's sidebar row shows "1 helper running", "N helpers running" or "N helpers finished"; clicking it opens a popover with the running helpers, then the finished ones newest first, each with its state, its task (the description Claude gave the subagent, else its agent type) and agent type, and how long it ran. Clicking a helper shows the first 8 lines of its final report (the subagent's handback or closing message), with Copy and Open Report (a markdown pane beside the focused pane); Clear removes the finished ones. It refreshes every second while open. Programa keeps up to 256 helpers in memory, so they do not come back after a restart, and a closed workspace's helpers go with it. OSC 7501 child records are not read as helpers on Windows.

Pane control works as on macOS ([socket API](../docs/socket-api.md)): `pane.list` (panes in layout order with their tabs, frame in DIPs, and the selected terminal's columns, rows and cell size), `pane.surfaces`, `pane.focus`, `pane.last`, `pane.create` (left, right, up or down of the focused pane), `pane.resize` (moves the pane's border on that side by `amount` DIPs, within 10-90% of the split), `pane.swap` (the two panes trade their selected tabs), `pane.break` (a tab into a new workspace of its own, its terminal carrying on), `pane.join` (a tab into another pane), `workspace.next`, `previous`, `last` (back through the workspaces you selected), `workspace.reorder` and `workspace.equalize_splits` (every pane the same share, or only the splits of one `orientation`). The CLI has `list-panes`, `list-pane-surfaces`, `focus-pane`, `new-pane`, `resize-pane -L|-R|-U|-D [--amount CELLS]`, `swap-pane`, `break-pane`, `join-pane`, `last-pane`, `next-window`, `previous-window`, `last-window` (workspaces, as macOS's tmux-style names) and `reorder-workspace`; `new-split` also takes left and up. As on macOS, only the focus methods move your selection.

App introspection works as on macOS ([socket API](../docs/socket-api.md)): `system.tree` returns the focused window (every window with `all_windows`, or the one holding `workspace_id`) with each workspace's title, directory, branch, pull request, nesting, agent state and helpers, and each pane's tabs with their type, title, directory, branch, agent and program state; `active` is where the focus is, and `caller` where a given workspace and tab are. `shortcuts.list` lists every shortcut as the app resolves it, `settings.open` opens Settings (`target: keyboardShortcuts` at Keyboard Shortcuts), `app.reload_config` applies settings.json and the terminal configuration now, `notification.create_for_surface` and `notification.create_for_target` post a notification for a given tab (its name after the title when it has one), and `feedback.open` opens the GitHub issues page (`feedback.submit` is disabled, as on macOS). The CLI has `shortcuts`, `list-shortcuts`, `reload-config` and `feedback`. Windows has no tty per tab and no shell activity reports, so those fields are null.

Session history works as on macOS ([snapshot restore](../docs/plans/snapshot-restore.md)): each launch first copies the session file into `%LOCALAPPDATA%Programasession-history<yyyyMMdd-HHmmss>-session.json` (`session-dev` for development builds), skipping a copy identical to the newest and keeping the 10 newest. A quit, or closing the last window, marks the session clean; autosaves mark it unclean. An unreadable session file falls back to the newest archive that restores. `snapshot.list` shows every archive with when it was saved, whether it was clean, and its window, workspace and tab counts; `snapshot.restore` (an id, or the newest) opens one as new windows with new ids, never touching an open window or a running shell; its tabs start new shells in their saved directories with their saved output. The CLI has `programa snapshot list` and `programa snapshot restore [<id>|latest]`.

Dragging a tab onto a pane works as on macOS: near an edge (the outer quarter, at least 80 pixels, left and right first at the corners) it splits that pane and the tab takes the new side, in the middle it joins the pane, and an accent placeholder shows where it goes. The edge a pane shares with the tab's own pane means "into this pane". A tab from another window works too. A pane's only tab split off its own pane leaves a new terminal behind. `surface.drag_to_split` (CLI `drag-surface-to-split --surface ID <left|right|up|down>`) splits a tab off its pane the same way.

Terminal input and tab actions work as on macOS ([socket API](../docs/socket-api.md)): `surface.send_key` (enter, tab, escape, backspace, delete, space, the arrows, home, end, page up/down, sigint, eof, sigtstp, sigquit, and ctrl, shift or alt with one of those or a letter; there is no Command key), `surface.send_paste` (one paste, never Return), `surface.send_if_unchanged` (sends text and keys only while the `fingerprint` `surface.read_text` now returns is unchanged, else `mismatch`), `surface.clear_history` (the scrollback; the screen stays, as with Ctrl+Shift+K), `surface.trigger_flash`, `surface.refresh`, `surface.health`, `surface.reorder` and `tab.action` (also `surface.action`): rename, clear_name, pin and unpin (a pinned tab shows a pin, stays first in its pane and is kept by the close actions), mark_read, mark_unread (a dot on the tab until you pick it), new_terminal_right, close_left, close_right and close_others. Keys, pastes and conditional sends refuse while an agent waits on an approval prompt (`answer_prompt` sends anyway) or someone has unsent typed input (`force`). The tab menu has Pin Tab and Unpin Tab. The CLI has `send-key`, `clear-history`, `trigger-flash`, `refresh-surfaces`, `surface-health`, `reorder-surface`, `tab-action` and `rename-tab`. A tab or split created over the socket leaves every workspace's selected pane and tab as they were.

Sidebar metadata works as on macOS ([socket API](../docs/socket-api.md)): `workspace.set_status`, `clear_status`, `list_status`, `log`, `clear_log`, `list_log`, `set_progress`, `clear_progress`, `report_meta_block`, `clear_meta_block`, `list_meta_blocks`, `sidebar_state` and `reset_sidebar`, with the same limits and replies, and the CLI commands `set-status`, `clear-status`, `list-status`, `set-progress`, `clear-progress`, `log`, `clear-log`, `list-log` and `sidebar-state`. A workspace's sidebar row shows its status entries by priority, then newest (three, then Show more), each with its icon (`emoji:`, `text:`, or an SF Symbol name mapped to a Segoe glyph when there is one), its color, and a link when it has a url; its markdown blocks (one, then Show more details); the latest log line with its level's icon, which is the status line when no agent reports; and the progress bar with its label. Status entries that repeat the agent pill (`claude_code` Running and the like) are left out. A session restore brings back the log (the last 50 entries) and the progress, not status entries or blocks. `pid` is checked but not used for ports, and `sidebar_state` has no dirty flag or PR checks (null).

Agent automation works as on macOS ([socket API](../docs/socket-api.md)). A surface's `agent_state` is `working`, `blocked` or `idle` (done and error read as idle), or none, with its `source`: `program` (the program's own OSC 7501 status), `hooks` (`surface.report_agent_state`, `agent.needs_input`) or `inferred` (screen detection), in that order of authority. `programa wait-surface` (`surface.wait`) holds one request until a surface's output matches `--pattern`, its shell `--exit`s, its `--agent-state` is `idle` (none counts), `working`, `blocked` or `any_change`, or its `--program-state` is reached, up to `--timeout` (30 s); it says `waited: false` when the condition already held, `closed` when the surface went away, and fails with `timeout` otherwise. `programa prompt-agent <text>` (`agent.prompt`) types the prompt and Return into an agent's terminal and waits for it to finish: it refuses while the agent waits on an approval prompt (`agent_awaiting_approval`; `--answer-prompt` sends anyway), holds while a person has typed something unsent there (since the last Return, Ctrl+C or Ctrl+U, within the last minute; `draft_in_progress` if it never ends, `--force` skips this) and lets that person's turn finish first, then waits up to `--working-grace` (3 s) for `working` and up to `--timeout` (120 s) for `idle`. Without any state reports it returns at once with a warning. `agent.needs_input` reports a surface blocked and posts its notification in one call. `programa watch-events` (`subscribe`/`unsubscribe`) streams JSON frames: `agent_state` changes, `output` of the surfaces given to `--output` (what was appended, read every 100 ms, at most 4000 characters), `workspace_lifecycle` (`created`, `closed`, and `renamed` for given names only) and `needs_input`; each subscription queues at most 256 frames, dropping the oldest and then sending `{"event":"dropped","count":N}`, and the CLI reconnects with backoff unless `--no-reconnect`.

Event routes work as on macOS ([programa.json routes](../docs/programa-json.md#routes)): the `routes` of `%USERPROFILE%\.config\programa\programa.json` (the global file only; JSON with comments) run `notify`, `send`, `prompt`, `run` or `review` on `agent/<surface>/state/<working|blocked|idle|none>`, `agent/<surface>/needs_input/<permission|question|unknown>` and `workspace/<id>/<created|closed|renamed>` events, with MQTT `+` and `#` topics, `when` conditions (equals, `ne`, `in`, `exists`, `regex` with `i`, `m`, `s`, `x` flags, all regexes sharing 50 ms per event), `debounceMs`, `throttleMs` and `key`, and every load rule (a route that does not load is listed under its issues and notified once, and the rest still load). They install again whenever the file's content changes, resetting counters. Programa keeps the macOS second view of each agent for routes: only hook reports move it (Windows signs no OSC 7501 status), so `run` and `review` act on Claude Code with its hooks and refuse states from unsigned status or screen detection, and `send` and `prompt` keep every macOS refusal (no agent, a prompt showing, typed input, no session, stopped for input, a first report), with `whenBusy` `queue` or `steer`, prompt turns, and the 600-second limits. A `run` command goes to PowerShell (`pwsh`, else Windows PowerShell) in the surface's reported directory, with the event's fields as `PROGRAMA_ROUTE_*` variables, at most 4 at a time, and a failure posts "Route “name” failed" with the end of its output. A question's built-in banner gives way to a notify route that matches it, a permission's only to one that fires for it. `cwd` is the directory the shell reported, `worktree` is `"true"` in a linked git worktree. `programa routes` (`routes.list`) lists the routes, their matched, fired, throttled, busy and expired counts and last errors, and the issues.

Right-click a workspace in the sidebar for the macOS workspace menu: Pin Workspace (pinned workspaces stay together at the top, with a pin after the title), Rename, Edit Workspace Description… (a line under the title), Workspace Color (the macOS palette, drawn as a bar along the row; Clear Color removes it), Move Up, Move Down, Move to Top, Close Other Workspaces and Close. `programa workspace-action <action>` runs the same actions, plus `close-above`, `close-below` and `mark-read`, over `workspace.action`; `--color` takes a palette name or `#RRGGBB`. Pin, color and description come back with the session.

Windows work as on macOS. **New Window** (`Ctrl+Alt+Shift+N`, or the command palette) opens a window with its own workspaces and sidebar. **Move Workspace to Window** in a workspace's menu sends it to another open window or a new one, and **Move Tab to New Window** (tab menu or palette) gives a tab a workspace of its own in a new window; either way its terminals keep running, with their output and running programs. Closing a window ends its workspaces, asking first when one runs a program; **Quit Programa** in the palette saves every window and closes them all, and the next launch restores every window that was open, at its place. Notifications, the Ports panel and the control pipe span all windows: a CLI command goes to the window that owns the ids it names, else to the window you used last. `programa list-windows`, `current-window`, `new-window`, `focus-window`, `close-window` and `move-workspace-to-window --window <id|new>` drive them, over `window.*` and `workspace.move_to_window`. `programa move-surface [--surface ID] (--pane ID | --workspace ID | --window ID|new) [--before ID | --after ID | --index N] [--focus true|false]` moves a tab over `surface.move`, as on macOS: to a pane, to a workspace's or window's selected pane, or to a new window, taking no focus unless `--focus true`. Dev builds also answer `debug.tab.tear_off` (`surface_id`, `x`, `y`), the tear-off a drag past every window does, and `debug.command_palette.toggle`, `debug.command_palette.results` and `debug.type`, which open the palette, list its rows, and type into its query (a newline runs the highlighted row).

Closing a window, or the last workspace, asks first when a terminal is still running a program (anything other than its shell at a prompt), as on macOS. Closing other tabs and workspaces, a shell exiting, and CLI closes do not ask.

Relaunch restores the session, as on macOS: every window with its workspaces, splits, tabs and the names you gave them, its sidebar and frame, and each terminal's directory, last 2000 lines of output and font size. Terminal processes survive Programa quitting or crashing, as on macOS: every shell runs in the terminal host, `programa-host.exe` (copied with Windows Terminal's `conpty.dll` and `OpenConsole.exe` to `%LOCALAPPDATA%\Programa\bin`), which keeps it and its last 4 MB of output while Programa is away, and the next launch reattaches each tab live: its screen is rebuilt from that output (without answering old terminal queries or repeating notifications), and the shell is resized to the tab. A layout's start command does not run again on a reattached tab. Closing a tab ends its shell once it can no longer be reopened (a few seconds), and closing one window of several ends its terminals; quitting, or closing the last window, does not, so the quit dialog asks only about programs a quit would end. The host exits a minute after its last shell ends, and a relaunch ends any shell whose tab no workspace restored. The host is found through `%LOCALAPPDATA%\Programa\terminal-host.json` (a random pipe name and token; development builds use `terminal-host-dev.json` and their own host), and a launch log line says whether it started or reconnected. When the host cannot start, or with `PROGRAMA_TERMINAL_HOST=0`, terminals run in the app as before and end with it: the saved output then comes back as scrollback above a fresh shell started in the saved directory. The session is saved every 30 seconds and on close to `%LOCALAPPDATA%\Programa\session.json` (development builds use `session-dev.json`); a file that cannot be read is set aside as `session.json.broken`. Closing the last workspace starts the next launch fresh.

New terminals start PowerShell 7 (`pwsh.exe`) when it is on `PATH`, else Windows PowerShell, else `COMSPEC`, with `TERM_PROGRAM=ghostty` and `COLORTERM=truecolor` as on macOS. Programs that track the mouse (Claude Code, OpenCode, vim) receive clicks, drags and the wheel; hold Shift to select text instead. Programs that enable the kitty keyboard protocol get unambiguous modified keys, so Shift+Enter inserts a newline in agents. OSC 52 copies reach the Windows clipboard. Ctrl+click opens a URL in the text or an OSC 8 hyperlink (⌘-click on macOS), and holding Ctrl over one underlines it. The font and colors follow Ghostty's defaults and your Ghostty config, as on macOS; see [Terminal themes](../docs/terminal-themes.md#windows).

## Validation

The Windows CI job is the reproducible compiler and test environment. Interactive validation must use Windows 11 and cover real shell startup, input, IME composition, copy and paste, tab drag in both directions, nested splits and divider resizing, 100/150/200% scaling, light/dark/high-contrast themes, keyboard-only navigation, and Narrator. macOS cannot validate WinUI XAML compilation, ConPTY, native UI Automation peers, or single-file extraction.

The `windows-build` CI job also runs `programa.exe --smoke`, which drives the real startup path (`Application.Start`, `MainWindow` created and activated, one terminal spawned) and fails the build if the window never shows or the first terminal snapshot never arrives.

## Troubleshooting

**Windows SmartScreen blocks the exe with a warning screen.** This is expected until the exe is code-signed; there is no signing certificate configured yet (see `docs/windows-testing.md`). Click **More info**, then **Run anyway**.

**Nothing appears after "Run anyway": no window, no error.** Programa writes a log of every launch to `%LOCALAPPDATA%\Programa\launch.log`, including a "launch ok: window shown" line on success and the full exception and stack trace on failure. If the app doesn't start, open that file (or run `type %LOCALAPPDATA%\Programa\launch.log` from a command prompt) and send its contents when reporting the issue. A native error dialog should also have appeared naming this same path.
