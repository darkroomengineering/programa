# Programa for Windows

Programa's Windows frontend uses C# on .NET 10 and native WinUI 3 controls. The portable Rust core owns workspace, pane, surface, selection, split, and tab-order behavior. `programa_terminal.dll` owns each ConPTY session and terminal model; the WinUI shell keeps one `TerminalView` alive per core surface ID so selecting, splitting, and reordering controls never restarts a shell.

## Build on Windows

Install the .NET 10 SDK, stable Rust MSVC toolchain, Visual Studio Build Tools with the Desktop development with C++ workload, and a current Windows SDK. Then run from PowerShell at the repository root:

```powershell
rustup default stable-msvc
rustup target add x86_64-pc-windows-msvc
./scripts/build-windows.ps1 -Version 0.4.123 -Build 123 -Commit 0123456789abcdef0123456789abcdef01234567 -OutputDirectory ./artifacts/windows
```

The output directory must be new or empty. The script formats and tests both Rust libraries, runs the managed projection tests, publishes the unpackaged self-contained WinUI application, validates its x64 PE header and exact `--version` output, and emits only these byte-identical files:

- `programa-windows.exe`
- `programa-windows-<build>.exe`

Windows App SDK single-file publishing extracts its bundled managed, WinUI, `programa_core.dll`, `programa_terminal.dll`, `conpty.dll` and `OpenConsole.exe` dependencies into the .NET single-file extraction area on first launch. The last two come from Microsoft's `Microsoft.Windows.Console.ConPTY` NuGet package (the ConPTY Windows Terminal ships): terminal sessions run on that `OpenConsole.exe` rather than the inbox conhost, which mangles OSC color queries and repaints the screen. `--verify-native-libraries` fails when either file is missing, and `launch.log` records `conpty=bundled` or `conpty=inbox` on every start. It does not download code or require a separately installed Windows App SDK runtime.

Release builds are signed via Azure Trusted Signing once the account is configured (see `docs/windows-signing.md`). Until then, `programa-windows.exe` ships unsigned and SmartScreen shows "Run anyway" the first time someone launches it.

For an ordinary development build after the native DLLs exist:

```powershell
dotnet build windows/Programa/Programa.csproj -p:ProgramaNativeDirectory=C:\path\to\native-dlls
```

A development build keeps its own control pipe (`programa-dev-%USERNAME%`), session, terminal host, MCP and hook files and WebView2 data under `%LOCALAPPDATA%\Programa`, apart from the installed app's. To run several development builds at once, as macOS `reload.sh --tag` builds do, start each with its own `PROGRAMA_DEV_TAG` (letters, digits and hyphens, up to 32): that build then uses `programa-dev-<tag>-%USERNAME%` and `-dev-<tag>` in each of those names. Installed builds ignore it.

```powershell
$env:PROGRAMA_DEV_TAG = "copy-mode"; Start-Process windows\Programa\bin\Debug\net10.0-windows10.0.19041.0\win-x64\programa.exe
```

## Windows behavior

The app uses WinUI `TabView` document tabs: drag a tab to reorder it, onto another pane's tab strip to move it there (in this window or another Programa window), or out past the edge of every Programa window to open it in a new window under the release point, as on macOS. Its terminal moves with it, still running with its scrollback. Released over a window but off a tab strip, a tab stays where it was; Escape cancels the drag; the app's only tab stays put. Each pane has its own tab strip, and recursive WinUI `Grid` layouts provide draggable native split dividers. Closing a pane's final tab collapses that pane; closing a workspace's final tab closes the workspace, and closing the last workspace closes the window. A resizable sidebar on the left lists the workspaces, as on macOS: 238 pixels wide by default, from 238 to 600 and never more than a third of the window. Each row shows the name you gave it (or the focused terminal's title, without an agent's leading spinner glyph while the row shows that agent's status), then one status line, then its description wrapped below; right-click a row, or click its ••• button, for the workspace menu. Hovering a row swaps its elapsed time for ••• and a close button; a middle-click closes it too. Drag a row to reorder it, drop a pane tab on a row to move the tab into that workspace, and double-click below the rows for a new workspace at the end. Ctrl-click and Shift-click pick several rows, and the menu then acts on all of them. Holding Ctrl on its own for a moment shows each row's Select Workspace shortcut (`Ctrl+1` to `Ctrl+8` and `Ctrl+9` for the last, or whatever they are bound to) in place of its close button. The list keeps its scroll position as it updates, and the window title follows the selected workspace. Switching workspaces keeps every terminal running.

Agent status follows the macOS sidebar indicator: each row shows the worst state among its terminals as a pill (Needs input, Working, Done, Error or Idle), the time since the last report, and the agent's logo (Claude Code, Codex, Copilot CLI, Cursor Agent, Gemini CLI or OpenCode: the macOS images, with light and dark versions of the one-color ones), which also replaces the tab icon; Aider has no logo, as on macOS. A working or needs-input agent with no report for 10 minutes reads "(stale)". The state comes from OSC 7501 program status, which Claude Code 2.1.295 and later sends on its own once the terminal answers its probe; nothing needs installing. Claude Code skips the probe when `CLAUDE_CODE_DISABLE_TERMINAL_TITLE` is set, which happens when Programa itself is started from inside a Claude Code session, so start it from the Start menu. Agents that report nothing themselves (Codex, OpenCode, Gemini CLI, Copilot CLI, Cursor Agent, Aider) get their status from the screen every 2 seconds, matched against the same manifests as macOS ([agent detection manifests](../docs/agent-detection-manifests.md)), with your overrides in `%USERPROFILE%\.config\programa\agent-detection`; a shell with nothing running under it ends the detection, and any OSC 7501 or `programa set-agent-state` report wins. Of the agent hooks, Windows runs Claude Code's (below); the badge still follows Claude's own status, and the hooks feed resume and event routes. The window uses the Mica backdrop, and its toolbar shares the title bar row as on macOS: Notifications, New Workspace and Toggle Sidebar sit at the sidebar's trailing edge, the Windows caption buttons at the right, and the rest of the row (including the sidebar's top) drags the window. The end of each pane's tab strip holds Split Right, Split Down, Zoom Pane (dimmed with one pane) and Close Tab, acting on that pane (the macOS 26 pane header). Settings and Help are at the foot of the sidebar. WinUI supplies keyboard focus, system theme and high-contrast behavior, accessibility peers, DPI scaling, and native dialogs.

Notifications follow macOS too. A program can ask for one with `OSC 777;notify;title;body` (Claude Code does, for permission prompts and when it waits for input) or `OSC 9;body`, and a terminal whose agent status enters Needs input, Done or Error posts one, at most once per 10 seconds per terminal. A terminal you are looking at never notifies. Otherwise a Windows notification appears, the tab gets a dot, its pane a ring while that tab is shown, the sidebar row an unread count, and the bell in the toolbar turns the accent color. The bell opens the notifications panel; clicking an entry or a Windows notification goes to its terminal, and looking at a terminal marks its notifications read. `Ctrl+Shift+U` jumps to the latest unread. As in the macOS popover, each entry has a dot (filled while unread), a clear button, and Mark as Read or Mark as Unread on right-click (one marked unread moves to the top); the header has Mark All Read and Clear All, and the panel redraws while it is open. When agents wait on you, the panel also has the macOS menu bar's "N agents blocked", which goes to the first one, as does **Jump to Blocked Agent** in the command palette (no shortcut, as on macOS). The tab menu has Mark Tab as Read or Unread, and the workspace menu Mark Workspace as Read, Mark Workspace as Unread and Clear Latest Notification, each enabled as on macOS; the command palette has Mark All Read while anything is unread.

The Help button at the foot of the sidebar has the macOS Help menu: Welcome to Programa! (a new workspace running `programa welcome`), Send Feedback, Keyboard Shortcuts (Settings at that section), Docs, Changelog, GitHub, GitHub Issues, X (Twitter) and Darkroom, then Check for Updates and About Programa, whose dialog shows the version, build and commit, links Docs and GitHub, and lists the third-party licenses (`THIRD_PARTY_LICENSES.md`, bundled). What macOS keeps in its app menu is in the command palette: Ghostty Settings… opens the Ghostty config the terminal reads (`%XDG_CONFIG_HOME%\ghostty` or `%USERPROFILE%\.config\ghostty`: `config.ghostty`, else `config`, else a new empty `config.ghostty`) in Notepad, where macOS uses TextEdit, and Reload Configuration applies it; Install Codex Integration… opens a workspace running `programa codex install-integration`, which asks before it changes anything; Show Welcome Screen, Check for Updates and About Programa are there too. Check for Updates opens the GitHub releases page: the Windows release publishes `programa-windows.exe` on `rolling` but no feed Velopack's updater can read, so the app does not update itself yet.

New terminals run PowerShell with Programa's shell integration, started after your profile with `-NoExit -EncodedCommand` so the script execution policy does not block it. At each prompt it reports the working directory (OSC 7), the prompt marks (OSC 133) and a title naming the directory, keeping whatever prompt your profile set. New tabs and splits start in the focused terminal's directory, and each sidebar row has one line per directory its terminals are in, in layout order: the git branch (read from the repository files, `*` after it when a shell reported the tree dirty) and the directory, left out when it is `~` or repeats the title. Under them, a link per pull request names it with its state icon ("PR #12 open"), each tab's branch looked up with the GitHub CLI (`gh pr list --head`) every 30 seconds as on macOS; without `gh` signed in, those lines stay hidden. Then come the ports its programs listen on, each a link to `localhost`. Windows does not probe git for a dirty tree on its own (macOS runs a hardened `git status`), so the `*` needs a `surface.report_git_branch` with `dirty`. Every terminal gets `PROGRAMA_SURFACE_ID`, `PROGRAMA_WORKSPACE_ID` and their older aliases, as on macOS.

Every terminal has the `programa` CLI on `PATH` (it ships as `bin\programa.exe` next to the app) and `PROGRAMA_SOCKET_PATH` naming the control pipe, `\\.\pipe\programa-%USERNAME%` (development builds use `programa-dev-%USERNAME%`). The CLI speaks the same v2 JSON lines as the macOS socket and covers `ping`, `identify`, `tree`, workspaces (`new-workspace`, `select-workspace`, `rename-workspace`, `close-workspace`), terminals (`new-surface`, `new-split`, `focus-surface`, `close-surface`, `send`, `read-screen`), notifications (`notify`, `list-notifications`, `clear-notifications`), ports (`list-ports`, `stop-port`), worktrees (`worktree create`, `open`, `remove`, `list`, and `race`), layouts (`layout save`, `apply`, `list`), windows (`list-windows`, `new-window`, `move-workspace-to-window` and more), `markdown open`, `review`, `resume`, `usage` and `set-agent-state`; `programa help` lists the flags. Commands default to the terminal they run in and never take focus, except `select-workspace` and `focus-surface`. The pipe accepts only the current user.

The rest of the macOS CLI works the same way: `current-workspace`, `list-panels`, `focus-panel`, `send-panel`, `send-key-panel`, `handoff` (another pane's last lines pasted into a prompt, never submitted), `recap open|list`, `rpc <method> [json]`, `agent-event`, `opencode-hook` and `welcome`, and the tmux-compatible `capture-pane`, `display-message`, `find-window`, `set-buffer`, `list-buffers`, `paste-buffer`, `pipe-pane`, `respawn-pane`, `set-hook` and `wait-for`. As on macOS, buffers and hooks are kept by the CLI in `%USERPROFILE%\.programa\tmux-compat-store.json` (hooks are stored, not run) and `wait-for` signals are files in `%USERPROFILE%\.programa\run\wait-for`. There is no tmux on Windows, so `pipe-pane` runs its command in PowerShell 7 when `pwsh` is on `PATH`, else Windows PowerShell, with the pane's text as UTF-8 on its stdin (`$input`), and `respawn-pane` with no command starts a new shell inside the current one, since PowerShell has no `exec`. `config check` and `themes` run the app headless (`programa.exe --check-settings`, `--themes`), so they use the app's own settings.json reader and writer and work while Programa is closed: the check reports the JSONC syntax, `app.appearance`, `app.terminalTheme`, `app.terminalFont` and `customCommands.trustedDirectories` with the macOS messages, and `themes` lists the bundled and `~/.config/ghostty/themes` themes and writes `app.terminalTheme` and `app.terminalFont`, which the running app reapplies; `--opacity`, `--blur` and `--no-blur` are macOS-only. `claude-teams` starts Claude Code with agent teams on and Programa's MCP server and hooks, but its teammates run inside the same pane (`--teammate-mode in-process`): on macOS a `tmux` shim opens them as Programa panes, while Claude Code's tmux backend runs a `tmux` executable and types POSIX shell command lines into the panes it opens, which a PowerShell pane cannot run.

`programa-mcp`, the MCP server agents use to drive Programa ([MCP server](../docs/mcp-server.md)), ships as `bin\programa-mcp.exe`, copied at launch with the `programa` CLI to `%LOCALAPPDATA%\Programa\bin` (the app itself unpacks to `%TEMP%`, which temp cleanup can empty). Claude Code started in a Programa terminal gets it automatically as a server named `programa`: the PowerShell integration wraps `claude` to pass `--mcp-config=` a config the app writes to `%LOCALAPPDATA%\Programa\mcp.json`, nothing is written to your Claude config, and your own `--mcp-config` or `--strict-mcp-config` and the `mcp` and `config` subcommands pass through untouched. Its tools are the running app's control methods (`surface_read_text`, `worktree_create`, `review_open` and so on, with the focus-moving ones named `focus_…`), with input schemas from the macOS contract, and its resources are `programa://tree` (every window) and `programa://surface/<id>/text?lines=n`. For another MCP client, point it at that executable; it finds the app through `PROGRAMA_SOCKET_PATH` or the default pipe.

The Ports button beside Settings counts the TCP ports that programs started from Programa terminals listen on, and appears only while one does. It opens Listening Ports, grouped by workspace, with Open in browser, Copy URL, Reveal in workspace and Stop for each, plus a Left running section for listeners whose terminal closed. Windows has no SIGTERM, so Stop asks first and then sends Ctrl+C through the program's terminal, force-stopping it if it still runs 3 seconds later; a process left running is force-stopped at once. `programa list-ports` and `programa stop-port <port>` (or `--pid`) do the same from a terminal, over `ports.list` and `ports.stop`. The list is rescanned every 3 seconds.

The drive button beside Settings opens Storage, as on macOS: free and total space on the home folder's drive; Live sessions, the disk use of each workspace directory (the home folder and drive roots left out) with its `node_modules`, `build`, `dist`, `.next`, `target` and similar folders of 50 MB or more; the removable linked worktrees of the repositories open in workspaces and under the worktrees folder, with why each other one is kept; and package manager caches (npm, pnpm, Yarn, Bun; Xcode and Android caches are macOS-only), with blocked ones and why. Worktree and cache results are kept five minutes, session sizes two. Each Clean lists what it would remove with sizes and paths and asks first; the worktree Clean skips the idle wait but keeps dirty, unmerged, open or env-file-holding worktrees, and removes with `git worktree remove` without `--force`, never deleting branches. A cache Clean runs the manager's own command (`npm cache clean --force`, `pnpm store prune`, `yarn cache clean`, `bun pm cache rm`), or empties the folder when the manager is not installed, and nothing is cleaned while that manager is installing. Cache paths must be named like a cache or store, outside any repository, reached without junctions. `programa storage scan` and `programa storage clean [--dry-run] [--include-external] [--now] [--path DIR]... [--packages | --caches] [--item ID]...` do the same from a terminal, over `storage.scan` and `storage.clean`. Windows cannot read another process's working directory, so a worktree a process works in is not reported as `process_running`; Windows refuses to delete it and the worktree is kept as `git_refused`. The six-hourly pass that removes merged worktrees also cleans idle package caches with `storage.autoCleanCaches` (default on): `pnpm store prune` every time, the other caches after 14 days unused. Free space is checked 60 seconds after launch and every 15 minutes; below `storage.lowDiskWarningGB` (default 20, `0` turns it off) a toast says so, once until space rises 5 GB above the threshold, and clicking it opens Storage. Both settings are in Settings > Storage.

The gauge button after Ports, Provider Usage, opens how much of your Claude and OpenAI rate limits is left, as on macOS, read each time it opens ("Loading usage…" until the first answer). Claude appears when the `claude` command is found (on `PATH`, `%USERPROFILE%\.local\bin` or `%APPDATA%\npm`), `claude auth status` says you are signed in, and Claude Code's statusline wrote `%USERPROFILE%\.claude\tmp\rate-limits.json` within the last hour (some setups never write it; Claude is then left out), with its Current session and Weekly rows. OpenAI appears when `codex` is found and signed in: `codex app-server` is asked for the account and the unified rate limits, with the plan, credits and reset credits in its header and its windows as Current window and Weekly. Each read has 5 seconds. Each row shows what is left, a bar that turns orange from 60% used and red from 85%, and when it resets; a provider that could not be read shows an error line, and with neither the panel says "No usage available". Settings > Sidebar > Show Provider Usage, or `sidebarAppearance.showClaudeQuota` in settings.json, hides the button.

`programa worktree create <branch>` checks out a git worktree and opens it as its own workspace named after the branch, as on macOS: an existing local branch is checked out, otherwise it is created from `--base` (default `HEAD`), at `--path` or `%USERPROFILE%\.programa\worktrees\<repo>\<branch-slug>`. `worktree open <path-or-branch>` opens an existing worktree (or returns the workspace already on it), `worktree list` marks the open ones, and `worktree remove` closes its workspace and removes the worktree, never the branch, refusing one with uncommitted changes unless `--force`. `--repo` defaults to the current directory, and nothing takes focus unless `--focus`. `--layout <name>` applies a saved layout rooted at the worktree. `programa race "<prompt>"` fans one prompt across `--n` agents (default 3, up to 8; `--agent claude|opencode|codex`), each on its own `<prefix>/<n>` worktree and workspace numbered after the existing ones, without taking focus. `worktree create --from-issue <n>` reads the GitHub issue with `gh issue view` and names the branch `issue-<n>-<title-slug>` (a branch you give wins); `--agent claude|opencode|codex` then starts that agent on the issue, pointed at a prompt file in `%TEMP%\programa-issue-prompts` (kept 7 days) so the issue text is never typed into the shell. `worktree open --all` opens every worktree of the repo not open yet. A worktree's workspace nests in the sidebar under its repository's worktree folder, else under the workspace open on the repository's main checkout, whose row becomes a folder with an arrow that collapses its worktrees; selecting a hidden one opens the folder, and a worktree's row has a branch badge after its title. **Use as Worktree Folder** in a top-level row's menu makes it its repository's folder before it has any worktrees, **New Worktree Workspace…** asks for a branch and opens its new worktree nested there, and **Stop Using as Worktree Folder** sends its worktrees back to the top level. Every 6 hours (first two minutes after launch), a worktree under the worktrees folder is removed with `git worktree remove`, its branch kept, when its branch is merged into the remote default branch (or its upstream was deleted), it has no changes, holds no ignored `.env*` file outside `node_modules` and no other ignored file outside build and dependency folders, no workspace is open on it, and it was not used for a day, as on macOS; `worktrees.directory`, `worktrees.autoRemoveMerged` and `worktrees.autoRemoveAfterHours` in settings.json apply, and each removal is written to `launch.log`.

Named layouts use the macOS files and format ([Saved layouts](../docs/programa-json.md#saved-layouts)), in `%USERPROFILE%\.config\programa\layouts`. `programa layout save <name>` records the selected workspace's splits, tab names and directories (relative to the focused terminal's directory); `layout apply <name>` opens it in a new workspace without taking focus, or fills a single-tab workspace given with `--workspace`; `layout list` lists them. A file can add `command`, `env` and `focus` per terminal by hand. The command palette has Save current layout…, Apply, Rename and Delete layout: <name>, and the built-in Agent and Shell and Three Agents presets, which run `claude`. A broken file shows its reason in the palette. The palette also lists the `commands` and `recipes` of `programa.json` ([programa.json](../docs/programa-json.md)) as Custom: and Recipe: <name>, searchable by their `keywords`: from the nearest `programa.json` at or above the focused terminal's directory, then `%USERPROFILE%\.config\programa\programa.json`, the nearer file winning a name both use (a file that does not load lists nothing and is noted in `launch.log`). A command types its text and Return into the focused terminal, or opens its `workspace` (directory, color, layout; `restart` `ignore`, `recreate` or `confirm` for one of that name); a recipe types its prompt without Return. Each `parameter` is asked for first and fills its `{{name}}`. Trust works as on macOS: anything from a project file asks first, showing exactly what will run (every surface's command, directory and variables for a workspace), until you tick Always trust commands from this folder, which trusts the git root (or the file's folder) for that file's current content; a later change to a command asks again. The global file is always trusted, and `confirm: true` always asks. Command text with control characters, and recipe text with line breaks, is refused. Trusted roots are kept in `%LOCALAPPDATA%\Programa\trusted-directories.json` and listed under Settings > Custom Commands, or set by `customCommands.trustedDirectories` in settings.json. Ctrl+Alt+Shift+C opens a new workspace running Claude Code in the focused terminal's directory (⌘⇧C on macOS, which is copy on Windows).

`programa markdown <file>` (or `markdown open <file>`) opens a markdown file in a new pane beside the terminal, as on macOS, without taking focus unless `--focus`; `--direction down` stacks it instead, and `--workspace` or `--window` opens it beside that workspace's or window's focused surface. It prints `OK surface=<id> pane=<id> path=<path>`; `markdown.open` replies with the same ids plus `source_surface_id`, `source_pane_id` and `target_pane_id`, and refuses a folder (`invalid_params`), a missing file (`not_found`) and an unreadable one (`permission_denied`). `--direction left` or `up` puts it before the terminal.

The panel matches the macOS one. It shows the file's path, then GitHub-flavored markdown (tables, task lists, code); `> [!NOTE]`, `TIP`, `IMPORTANT`, `WARNING` and `CAUTION` alerts render as tinted callouts; ```` ```mermaid ```` blocks render as diagrams with the same offline `mermaid.min.js` macOS bundles (bundled in `programa.exe` as `Markdown\mermaid.min.js`, so no network), themed light or dark with the app, as wide as the panel up to the diagram's own size, and a diagram that does not parse stays as its source in a code block. A `:::compare` block holding two fenced code blocks shows them as Before and After panes, side by side when the panel is wide enough and stacked otherwise; a fence labeled `before` or `after` after its language (```` ```swift after ````) takes that side, else the first is Before, and any other `:::compare` block renders as plain markdown. The panel reloads in place when the file changes on disk, keeping the scroll, shows File unavailable while the file is deleted, and reads only the first 2 MB of a larger file, with a notice (UTF-8, else Latin-1, as on macOS; UTF-16 files with a byte order mark too). It follows the app's light or dark mode. Find (Ctrl+Shift+F, or Ctrl+F in the page) opens WebView2's find bar, and Find Next, Find Previous and Hide Find work on it; text selects and copies as usual. Web and mail links open in your browser, links to `.md` and `.markdown` files open in a new tab in the same pane (relative links resolve from the file's folder, `../` included), and other files or schemes open in their default app after an "Open in the default app?" prompt. Scripts in the file never run: the page allows only its own script and `mermaid.min.js`. The panel comes back with the session.

The diff review panel works as on macOS: **Review changes** in the command palette, or `programa review open`, splits a panel beside a terminal showing its uncommitted changes (`git diff HEAD` plus untracked files; `--mode branch --base-branch <ref>` diffs the branch since its merge base instead). Click a line number to comment, Shift+click to extend the range, Ctrl+Enter to add; **Send to agent** pastes every comment into that terminal as `path:start-end — text` lines under "Code review comments (N):" and submits them, refusing while its agent waits on an approval prompt. The panel refreshes itself when the agent finishes a turn, keeps comments whose lines moved (flagged), and comes back with the session (comments do not). `programa review refresh`, `review comment add|remove|list` and `review send` work on the panel from the CLI. Each time an agent starts a turn (its status goes to Working from idle or done; a prompt answered mid-turn is the same turn), its repository's files, tracked and untracked, are saved as a checkpoint under `refs/programa/checkpoints/`, never touching the index, `HEAD` or branches; the newest 20 per tab are kept, and a turn with over 500 changed paths or an untracked file over 10 MB is skipped. The review panel's **Revert Files to Before Last Turn** puts the files back as they were (the conversation is not rewound), saving the current files first so the same button then reads **Undo File Revert**. Closing a workspace deletes its checkpoints.

Each terminal also remembers the last Claude Code session it ran and saves it with the session, for when its shell did not survive (a reboot, or no terminal host). After a relaunch, **Resume Agent Session** in the command palette (shown when the focused terminal has one and nothing runs in it) or `programa resume` types `claude --resume <id>` at its prompt, entering the session's directory first when the terminal is elsewhere; `--print` prints the command instead, and `--session <id> --provider claude|codex|opencode` resumes a given id. The session is the one Claude Code reports through its SessionStart hook: the PowerShell `claude` function also passes `--settings=` a file the app writes to `%LOCALAPPDATA%\Programa\claude-hooks.json`, whose hooks run `programa claude-hook`, as the macOS wrapper's do, each report carrying Claude's session id: SessionStart sends `agent.event` `session.started` and `idle`, UserPromptSubmit `working`, Stop `idle`, Notification `agent.needs_input` (a permission request, or a wait for you as a question; anything else is a notification and `idle`), PostToolUse (and PostToolUseFailure) resumes `working` and clears the workspace's notifications, and SessionEnd sends `session.exited`, clears the state and stops the session's running helpers. As on macOS, PermissionRequest records which agent of the pane has a prompt open (`%TEMP%\programa-claude-permission-*`), so a subagent's finished tool never ends the main agent's stop for input, and PreToolUse (async) keeps an open AskUserQuestion, whose notification then reads as that question instead of a permission request. Your own `--settings` passes through, and your own hooks still run. Claude started without the function (its full path, another shell) falls back to the newest session Claude Code wrote in the terminal's directory (`%USERPROFILE%\.claude\projects`) when a turn ended. The hooks also keep each live session's workspace, pane, directory and transcript in `%USERPROFILE%\.programa\claude-hook-sessions.json` (7 days), and SessionEnd moves it to `agent-last-sessions.json` (one per pane, 50, 7 days), as on macOS. `programa usage [--workspace ID] [--json]` lists those sessions by workspace with the tokens each transcript records ([agent-usage.md](../docs/agent-usage.md)): input, output, cache read and cache write, every message counted once, subagent transcripts included, no cost. A session without a transcript path is found by id under `%CLAUDE_CONFIG_DIR%` (default `%USERPROFILE%\.claude`) or `%CODEX_HOME%` (default `%USERPROFILE%\.codex`), one whose transcript is gone is skipped and counted, and a closed workspace shows by its id.

**Resume Agents on Restart** (Settings > General, `app.autoResumeAgents`, on by default) does that for you, as on macOS: the session also records whether the agent was still running at quit (its shell busy and its tab showing that agent), and a restored terminal whose shell did not survive types the resume command at its first prompt. A shell the terminal host kept running is reattached as it is, agent included, and nothing is typed. A Claude session whose transcript is no longer under `%USERPROFILE%\.claude\projects` is not resumed. Turned off, restored terminals start a plain shell and Resume Agent Session still works.

**Stop Leftover Agent Processes** (Settings > General, `app.reapLeftoverAgentProcesses`, on by default) stops what a Claude Code session started and left running (dev servers, MCP servers and their browsers, debug builds) when the session exits, as on macOS. Windows forgets a process's parent once that parent exits, and Claude's Bash tool runs each command in a short-lived Git Bash, so Programa does not walk the process tree at exit: it puts each terminal's shell in a Windows job object (while the setting is on, from the shell's first seconds; a shell reattached after a restart joins with what it runs, as far as Windows lets it), and records, as each process in the job starts, which of the shell's children it descends from. A child is a Claude Code session when it is `claude.exe` or when the tab shows Claude Code while it runs. Two seconds after a session exits, every process recorded under it that still runs is terminated (Windows has no `SIGTERM`), and each exit is logged to `launch.log` under `reaper` with what was stopped. The `nohup` exemption is the same as on macOS: Claude Code's Bash tool on Windows is Git Bash, which has `nohup`, and a process that `nohup` started (or that descends from one it started) is kept, as is anything you start yourself. The job sets no limits and does not allow breakaway (Git Bash would otherwise start every native program outside it), so while the setting is on, a program in a Programa terminal that starts a child with `CREATE_BREAKAWAY_FROM_JOB` gets an access-denied error for it. Turned off, shells are no longer put in a job, and sessions that exit stop nothing.

Codex reports to Programa once you run `programa codex install-integration` (as on macOS; it shows the changes and asks first, `--yes` skips the question): it adds Programa's SessionStart, UserPromptSubmit, Stop, PermissionRequest and SessionEnd hooks to `%CODEX_HOME%\hooks.json` (default `%USERPROFILE%\.codex`), leaving your other hooks where they are, and trusts them in `config.toml` between `# BEGIN programa` and `# END programa`, since Codex skips hooks nobody trusted; a trust entry you wrote yourself is left alone with a warning. If Codex still lists them as new under `/hooks`, trust them there. Codex runs hooks through `cmd.exe` on Windows, so each is `if exist "<programa.exe>" "<programa.exe>" codex-hook <event>` and does nothing once Programa is gone or outside a Programa terminal. The hooks report Codex's session (so **Resume Agent Session** and `programa resume` type `codex resume <id>`), Working on a prompt, Needs input on a permission request (with the command it wants to run), Idle when it stops, and the end of the session, which `programa usage` then counts from Codex's rollout transcript. `programa codex uninstall-integration` removes exactly what it added.

Shell telemetry works as on macOS ([socket API](../docs/socket-api.md)): `surface.report_pwd` (an absolute path, without . or .. parts; a remote POSIX path is taken too), `report_git_branch` (with `dirty`), `report_pr` (number, url, state, checks and a label such as MR), `report_ports`, `report_shell_state` (prompt or running; a repeat comes back `deduped`), `report_tty`, and their `clear_*` counterparts are fire and forget: the arguments are checked and echoed, and a report for a tab that is gone does nothing. App introspection works as on macOS ([socket API](../docs/socket-api.md)): `system.tree` returns the focused window (every window with `all_windows`, or the one holding `workspace_id`) with each workspace's title, directory, branch, pull request, nesting, agent state and helpers, and each pane's tabs with their type, title, directory, branch, agent and program state; `active` is where the focus is, and `caller` where a given workspace and tab are. `shortcuts.list` lists every shortcut as the app resolves it, `settings.open` opens Settings (`target: keyboardShortcuts` at Keyboard Shortcuts), `app.reload_config` applies settings.json and the terminal configuration now, `notification.create_for_surface` and `notification.create_for_target` post a notification for a given tab (its name after the title when it has one), and `feedback.open` opens the GitHub issues page (`feedback.submit` is disabled, as on macOS). `app.browsers` lists the browsers that ship for Windows (Chrome, Firefox, Arc, Brave, Edge, Zen, Vivaldi, Opera, Opera GX, Perplexity Comet, Floorp, Waterfox, Sidekick and Chromium, with the macOS keys), each installed when it registers under `Clients\StartMenuInternet` or runs, its registered client name as `bundle_id`, and the key of the https handler you chose as `default` (its ProgId when it is none of these). Every terminal gets that key as `PROGRAMA_DEFAULT_BROWSER` and the ProgId as `PROGRAMA_DEFAULT_BROWSER_BUNDLE_ID`. Who may use the pipe is **Socket Control Mode** (Settings > Automation, `automation.socketControlMode`), as on macOS, and in every mode the pipe admits only your Windows user: **Programa processes only** (the default) admits a client whose ancestors include this app or its terminal host (every terminal's shell runs under the host), read from the client's pid (`GetNamedPipeClientProcessId`) up its parents, each of which must have started before its child so a reused pid cannot pass; **Automation mode** admits any process of yours; **Off** refuses every request; and **Password mode** admits Programa terminals as usual and any other process of yours once it sends `auth.login` with the password, **Socket Password** there (`automation.socketPassword` in settings.json, written by that row; Clear removes it). macOS's CLI reads the saved password itself, so its terminals never notice password mode; on Windows they need no login instead. The `programa` CLI and `programa-mcp` log in with `PROGRAMA_SOCKET_PASSWORD` when it is set. A refused client gets one v2 error, `access_denied`, `unavailable` (off), `auth_required` or `auth_failed`, and five wrong passwords close the connection; after five failures in a row, logins are refused for a second, doubling up to a minute, until one succeeds. `allowAll` and the legacy names (`openAccess`, `fullOpenAccess`, `full`, `notifications`) mean Automation mode on Windows, since the pipe never admits other users. A connection keeps the mode it connected under. `auth.login` from an admitted client succeeds with `required: false`. The CLI has `shortcuts`, `list-shortcuts`, `reload-config` and `feedback`. A tab's tty and shell state are null until its shell reports them.

Session history works as on macOS ([snapshot restore](../docs/plans/snapshot-restore.md)): each launch first copies the session file into `%LOCALAPPDATA%\Programa\session-history\<yyyyMMdd-HHmmss>-session.json` (`session-dev` for development builds), skipping a copy identical to the newest and keeping the 10 newest. A quit, or closing the last window, marks the session clean; autosaves mark it unclean. An unreadable session file falls back to the newest archive that restores. `snapshot.list` shows every archive with when it was saved, whether it was clean, and its window, workspace and tab counts; `snapshot.restore` (an id, or the newest) opens one as new windows with new ids, never touching an open window or a running shell; its tabs start new shells in their saved directories with their saved output. The CLI has `programa snapshot list` and `programa snapshot restore [<id>|latest]`.

Dragging a tab onto a pane works as on macOS: near an edge (the outer quarter, at least 80 pixels, left and right first at the corners) it splits that pane and the tab takes the new side, in the middle it joins the pane, and an accent placeholder shows where it goes. Terminal input and tab actions work as on macOS ([socket API](../docs/socket-api.md)): `surface.send_key` (enter, tab, escape, backspace, delete, space, the arrows, home, end, page up/down, sigint, eof, sigtstp, sigquit, and ctrl, shift or alt with one of those or a letter; there is no Command key), `surface.send_paste` (one paste, never Return), `surface.send_if_unchanged` (sends text and keys only while the `fingerprint` `surface.read_text` now returns is unchanged, else `mismatch`), `surface.clear_history` (the scrollback; the screen stays, as with Ctrl+Shift+K), `surface.trigger_flash`, `surface.refresh`, `surface.health`, `surface.reorder` and `tab.action` (also `surface.action`): rename, clear_name, pin and unpin (a pinned tab shows a pin instead of its close button, ignores a middle-click, stays first in its pane and is kept by the close actions), mark_read, mark_unread (a dot on the tab until you pick it), new_terminal_right, close_left, close_right and close_others. Sidebar metadata works as on macOS ([socket API](../docs/socket-api.md)): `workspace.set_status`, `clear_status`, `list_status`, `log`, `clear_log`, `list_log`, `set_progress`, `clear_progress`, `report_meta_block`, `clear_meta_block`, `list_meta_blocks`, `sidebar_state` and `reset_sidebar`, with the same limits and replies, and the CLI commands `set-status`, `clear-status`, `list-status`, `set-progress`, `clear-progress`, `log`, `clear-log`, `list-log` and `sidebar-state`. Agent automation works as on macOS ([socket API](../docs/socket-api.md)). A surface's `agent_state` is `working`, `blocked` or `idle` (done and error read as idle), or none, with its `source`: `program` (the program's own OSC 7501 status), `hooks` (`surface.report_agent_state`, `agent.needs_input`) or `inferred` (screen detection), in that order of authority. `programa wait-surface` (`surface.wait`) holds one request until a surface's output matches `--pattern`, its shell `--exit`s, its `--agent-state` is `idle` (none counts), `working`, `blocked` or `any_change`, or its `--program-state` is reached, up to `--timeout` (30 s); it says `waited: false` when the condition already held, `closed` when the surface went away, and fails with `timeout` otherwise. `programa prompt-agent <text>` (`agent.prompt`) types the prompt and Return into an agent's terminal and waits for it to finish: it refuses while the agent waits on an approval prompt (`agent_awaiting_approval`; `--answer-prompt` sends anyway), holds while a person has typed something unsent there (since the last Return, Ctrl+C or Ctrl+U, within the last minute; `draft_in_progress` if it never ends, `--force` skips this) and lets that person's turn finish first, then waits up to `--working-grace` (3 s) for `working` and up to `--timeout` (120 s) for `idle`. Without any state reports it returns at once with a warning. `agent.needs_input` reports a surface blocked and posts its notification in one call. `notification.claim_banners` (`kinds: ["needs_input"]`, `[]` to release) lets a connection show those toasts itself while it stays open, as Mesinyer does on macOS: the notification is still listed, in the sidebar and sent to subscribers, only the toast is skipped, for a notify route on that event too, and the claim ends when the connection closes. `programa watch-events` (`subscribe`/`unsubscribe`) streams JSON frames: `agent_state` changes, `output` of the surfaces given to `--output` (what was appended, read every 100 ms, at most 4000 characters), `workspace_lifecycle` (`created`, `closed`, and `renamed` for given names only) and `needs_input`; each subscription queues at most 256 frames, dropping the oldest and then sending `{"event":"dropped","count":N}`, and the CLI reconnects with backoff unless `--no-reconnect`.

Event routes work as on macOS ([programa.json routes](../docs/programa-json.md#routes)): the `routes` of `%USERPROFILE%\.config\programa\programa.json` (the global file only; JSON with comments) run `notify`, `send`, `prompt`, `run` or `review` on `agent/<surface>/state/<working|blocked|idle|none>`, `agent/<surface>/needs_input/<permission|question|unknown>` and `workspace/<id>/<created|closed|renamed>` events, with MQTT `+` and `#` topics, `when` conditions (equals, `ne`, `in`, `exists`, `regex` with `i`, `m`, `s`, `x` flags, all regexes sharing 50 ms per event), `debounceMs`, `throttleMs` and `key`, and every load rule (a route that does not load is listed under its issues and notified once, and the rest still load). They install again whenever the file's content changes, resetting counters. Programa keeps the macOS second view of each agent for routes: only hook reports move it (Windows signs no OSC 7501 status), so `run` and `review` act on Claude Code with its hooks and refuse states from unsigned status or screen detection, and `send` and `prompt` keep every macOS refusal (no agent, a prompt showing, typed input, no session, stopped for input, a first report), with `whenBusy` `queue` or `steer`, prompt turns, and the 600-second limits. A `run` command goes to PowerShell (`pwsh`, else Windows PowerShell) in the surface's reported directory, with the event's fields as `PROGRAMA_ROUTE_*` variables, at most 4 at a time, and a failure posts "Route “name” failed" with the end of its output. A question's built-in banner gives way to a notify route that matches it, a permission's only to one that fires for it. `cwd` is the directory the shell reported, `worktree` is `"true"` in a linked git worktree. `programa routes` (`routes.list`) lists the routes, their matched, fired, throttled, busy and expired counts and last errors, and the issues.

Right-click a workspace in the sidebar for the macOS workspace menu, in its order: Pin Workspace (pinned workspaces stay together at the top, with a pin after the title), Rename Workspace…, Remove Custom Workspace Name, Edit Workspace Description… (wrapped under the status line), Clear Workspace Description, the worktree folder items, Workspace Color (Clear Color, Choose Custom Color… for any `#RRGGBB`, then the macOS palette, drawn as a bar along the row), Move Up, Move Down, Move to Top, Move Workspace to Window, Close Workspace, Close Other Workspaces, Close Workspaces Below and Close Workspaces Above. Items show their shortcut, items that would do nothing at the list's edges are disabled, and the remove and clear items only appear when there is something to remove. With several rows picked, Pin, Color, Move to Top, Move to Window and Close act on all of them (closing several asks once, listing them), and Close Other Workspaces keeps them all. `programa workspace-action <action>` runs the same actions, plus `close-above`, `close-below`, `mark-read` and `mark-unread`, over `workspace.action`; `--color` takes a palette name or `#RRGGBB`. Pin, color and description come back with the session.

Windows work as on macOS. **New Window** (`Ctrl+Alt+Shift+N`, or the command palette) opens a window with its own workspaces and sidebar. **Move Workspace to Window** in a workspace's menu sends it to another open window or a new one, and **Move Tab…** in a tab's menu sends a tab to a new workspace, a new window or any workspace of any window, and **Move Tab to New Window** in the palette gives it a workspace of its own in a new window; either way its terminals keep running, with their output and running programs. Closing a window ends its workspaces, asking first when one runs a program; **Quit Programa** in the palette saves every window and closes them all, and the next launch restores every window that was open, at its place. Notifications, the Ports panel and the control pipe span all windows: a CLI command goes to the window that owns the ids it names, else to the window you used last. `programa list-windows`, `current-window`, `new-window`, `focus-window`, `close-window` and `move-workspace-to-window --window <id|new>` drive them, over `window.*` and `workspace.move_to_window`. `programa move-surface [--surface ID] (--pane ID | --workspace ID | --window ID|new) [--before ID | --after ID | --index N] [--focus true|false]` moves a tab over `surface.move`, as on macOS: to a pane, to a workspace's or window's selected pane, or to a new window, taking no focus unless `--focus true`. Dev builds also answer `debug.tab.tear_off` (`surface_id`, `x`, `y`), the tear-off a drag past every window does, and `debug.command_palette.toggle`, `debug.command_palette.results`, `debug.type` and `debug.shortcut.simulate`, which open the palette, list its rows, type into its query (a newline runs the highlighted row, and with no palette open the keys go to a terminal in copy mode, Escape and control characters included), and run the action bound to a key combination (`combo`, written as in settings.json, such as `ctrl-shift-g`). `debug.menu.open` (`surface_id`, `kind` `tab` or `terminal`) opens that tab's or terminal's menu as a right-click does, for UI Automation; `debug.sidebar.menu` (`workspace_id`) lists a sidebar row's menu as it would open now, or with `invoke` runs the item with that text; and `debug.sidebar.hints` (`show`) shows or hides the rows' shortcut hints.

Closing asks first as on macOS: a window or a workspace when a terminal in it is still running a program (anything other than its shell at a prompt), a pinned workspace always, and a workspace’s last tab even when nothing runs, since closing it closes the workspace (or the window, for the last workspace); `app.confirmCloseLastPane: false` drops that last ask. Closing other tabs, a shell exiting, and CLI closes do not ask. New workspaces go after the selected one (`app.newWorkspacePlacement`: `top`, `afterCurrent` or `end`; pinned workspaces stay first, and worktree workspaces stay under their parent).

Relaunch restores the session, as on macOS: every window with its workspaces, splits, tabs and the names you gave them, its sidebar and frame, and each terminal's directory, last 2000 lines of output and font size. Terminal processes survive Programa quitting or crashing, as on macOS: every shell runs in the terminal host, `programa-host.exe` (copied with Windows Terminal's `conpty.dll` and `OpenConsole.exe` to `%LOCALAPPDATA%\Programa\bin`), which keeps it and its last 4 MB of output while Programa is away, and the next launch reattaches each tab live: its screen is rebuilt from that output (without answering old terminal queries or repeating notifications), and the shell is resized to the tab. A layout's start command does not run again on a reattached tab. Closing a tab ends its shell once it can no longer be reopened (a few seconds), and closing one window of several ends its terminals; quitting, or closing the last window, does not, so the quit dialog asks only about programs a quit would end. The host exits a minute after its last shell ends, and a relaunch ends any shell whose tab no workspace restored. The host is found through `%LOCALAPPDATA%\Programa\terminal-host.json` (a random pipe name and token; development builds use `terminal-host-dev.json` and their own host), and a launch log line says whether it started or reconnected. When the host cannot start, or with `PROGRAMA_TERMINAL_HOST=0`, terminals run in the app as before and end with it: the saved output then comes back as scrollback above a fresh shell started in the saved directory. The session is saved every 30 seconds and on close to `%LOCALAPPDATA%\Programa\session.json` (development builds use `session-dev.json`); a file that cannot be read is set aside as `session.json.broken`. Closing the last workspace starts the next launch fresh.

New terminals start the program in your Ghostty config's `command`, as on macOS, unless `windows.shell` in settings.json replaces it, with `initial-command` instead for the first terminal a launch starts; without one, PowerShell 7 (`pwsh.exe`) when it is on `PATH`, else Windows PowerShell, else `COMSPEC`. Quote a program path that has spaces and put its arguments after it, for example `command = "C:\Program Files\Git\bin\bash.exe" --login -i`, `command = cmd.exe`, `command = wsl.exe ~` or `command = powershell -NoProfile`; arguments reach the program as written, and a program that cannot be found starts the default shell, with a line in `%LOCALAPPDATA%\Programa\launch.log`. PowerShell keeps Programa's shell integration. Other shells lose what it reports: the working directory (OSC 7) the sidebar, new splits and session restore use, the prompt marks (OSC 133) prompt jumps use, the directory as the tab title, and the `claude` wrapper that gives Claude Code Programa's hooks and MCP server; a layout's start command is typed after 5 seconds instead of at the first prompt. Terminals get `TERM_PROGRAM=ghostty` and `COLORTERM=truecolor` as on macOS. Programs that track the mouse (Claude Code, OpenCode, vim) receive clicks, drags and the wheel; hold Shift to select text instead. Programs that enable the kitty keyboard protocol get unambiguous modified keys, so Shift+Enter inserts a newline in agents. OSC 52 copies reach the Windows clipboard. Ctrl+click opens a URL in the text or an OSC 8 hyperlink (⌘-click on macOS), and holding Ctrl over one underlines it. The font and colors follow Ghostty's defaults and your Ghostty config, as on macOS; see [Terminal themes](../docs/terminal-themes.md#windows).

Terminal copy mode (`Ctrl+Shift+M`, ⌘⇧M on macOS) selects and copies with the keyboard, with the macOS keys, while a "vim" badge shows at the top right: `h` `j` `k` `l` or the arrows move a cursor of its own through the screen and scrollback, `0` `^` `$` go to the line's start, first text and end, `Ctrl+U` `Ctrl+D` move half a page and `Ctrl+B` `Ctrl+F` or PgUp and PgDn a page, `gg` or Home goes to the top of scrollback and `G` or End back to the prompt, and a number before a key repeats it. `v` starts a selection at the cursor that follows it, `y` copies it and leaves; without a selection `yy` copies the cursor's line and `3Y` three lines. `/` opens the find bar, `n` and `N` go to the next and previous match (the cursor goes there too), `{` and `}` go to the previous and next shell prompt (the rows PowerShell's integration marks with OSC 133;A), and Escape or `q` leaves. Keys typed in copy mode never reach the shell.

These follow the macOS defaults: a ⌘ shortcut takes `Ctrl+Shift`, or adds `Alt` when that is taken, and the ⌥⌘ ones use `Ctrl+Alt+Shift`, since `Ctrl+Alt` with a letter is AltGr on many keyboard layouts. Full screen, closing a window and feedback take the Windows keys.

Settings (`Ctrl+,`) has the macOS sections that apply on Windows, written to the same `%USERPROFILE%\.config\programa\settings.json` keys: General (`app.appearance` system, light or dark; `app.warnBeforeQuit`, which makes Quit Programa always ask; `app.newWorkspacePlacement`; `app.confirmCloseLastPane`; `app.commandPaletteSearchesAllSurfaces`, which adds every workspace’s tabs to Go to workspace; `app.autoResumeAgents` and `app.reapLeftoverAgentProcesses`, described above; `app.saveScrollbackOnQuit`, which with it off keeps terminal output out of the saved session and shows none from an earlier one; the settings.json path with an Open button, also in the command palette as Open settings.json; and Reset All Settings, which after a confirmation removes from settings.json every key this window writes, shortcuts included, so each row is back to its default, as macOS's button resets its rows; trusted folders, the socket password and the apps allowed to open links are kept, as on macOS, and so are macOS-only keys and comments), Terminal (`app.terminalTheme` light and dark themes from the bundled Ghostty themes or your own, and `app.terminalFont` family and size; empty keeps the Ghostty config), Notifications (Notification Sound, `notifications.sound`, picks one of Windows' toast sounds, Default, Instant Message, Mail, Reminder or Text Message, or None, with Play Sound to hear it from your Windows sound scheme; the file keeps macOS names, so the choice is written as `default`, `Ping`, `Glass`, `Hero`, `Pop` or `none`, and every macOS name plays the Windows sound closest to it: Tink and Morse play Instant Message, Purr and Bottle Mail, Submarine, Blow and Funk Reminder, Frog, Basso and Sosumi Text Message, and an unknown name the default; a name you leave alone is not rewritten; and whether Windows shows Programa’s notifications, with a link to its notification settings), Worktrees (`worktrees.directory`, `autoRemoveMerged`, `autoRemoveAfterHours`), Automation (`automation.claudeCodeIntegration`, which gives Claude Code Programa’s hooks and MCP server; `automation.claudeTeamsByDefault`, which starts plain `claude` with agent teams on, teammates in its pane, unless `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` is already set; both for new terminals; and `automation.holdAgentTextWhileTyping` and `automation.protectApprovalPrompts`, which turn off the `draft_in_progress` and `agent_awaiting_approval` refusals of `surface.send_text`, `send_key`, `send_paste`, `send_if_unchanged`, `agent.prompt` and the review panel’s Send; Socket Control Mode and Socket Password, described above; and `automation.agentScreenDetection`, which with it off stops reading agent status off the screen for agents without hooks, Claude Code's and Codex's hooks unaffected) and Keyboard Shortcuts, where each row is a recorder, as on macOS: click it and press the new keys; Escape keeps the old binding, Backspace removes it, and a binding another action has, or one the terminal keeps, is refused on the spot. The sections are listed down the left. When settings.json has problems, a banner at the top lists the first ones, as `programa config check` reports them. Only the values you change are written; every other byte of the file, comments and macOS-only keys included, stays. Changes apply to every window at once, and so does editing settings.json by hand, which Programa watches as macOS does; each terminal keeps its own Ctrl+=/Ctrl+- zoom. Shortcuts are stored under `windows.shortcuts`; saving rejects duplicate or malformed ones, a bad hand edit keeps the shortcuts in use, and raw `Ctrl+C`, `Ctrl+D`, and `Ctrl+W` stay reserved for the terminal. English and Japanese UI resources ship with the executable.

Set `windows.shell` and `windows.startingDirectory` in the same file to use a different shell and directory for new terminals. Both settings take absolute paths. `windows.shell` replaces Ghostty's `command`, and PowerShell keeps Programa's shell integration. `windows.startingDirectory` applies when a terminal has no directory to inherit from the one it was opened from. To launch PowerShell 7 in a local checkout, add these keys to the `windows` object with paths from your machine:

```json
{
  "windows": {
    "shell": "C:\\Program Files\\PowerShell\\7\\pwsh.exe",
    "startingDirectory": "C:\\Projects\\programa"
  }
}
```

## Validation

The Windows CI job is the reproducible compiler and test environment. Interactive validation must use Windows 11 and cover real shell startup, input, IME composition, copy and paste, tab drag in both directions, nested splits and divider resizing, 100/150/200% scaling, light/dark/high-contrast themes, keyboard-only navigation, and Narrator. macOS cannot validate WinUI XAML compilation, ConPTY, native UI Automation peers, or single-file extraction.

The `windows-build` CI job also runs `programa.exe --smoke`, which drives the real startup path (`Application.Start`, `MainWindow` created and activated, one terminal spawned) and fails the build if the window never shows or the first terminal snapshot never arrives.

## Troubleshooting

**Windows SmartScreen blocks the exe with a warning screen.** This is expected until the exe is code-signed; there is no signing certificate configured yet (see `docs/windows-testing.md`). Click **More info**, then **Run anyway**.

**Nothing appears after "Run anyway": no window, no error.** Programa writes a log of every launch to `%LOCALAPPDATA%\Programa\launch.log`, including a "launch ok: window shown" line on success and the full exception and stack trace on failure. If the app doesn't start, open that file (or run `type %LOCALAPPDATA%\Programa\launch.log` from a command prompt) and send its contents when reporting the issue. A native error dialog should also have appeared naming this same path.
